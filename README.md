# 墨页

v3 · 安卓原生（Kotlin）横屏 PDF 阅读 / 书写应用。系统 `PdfRenderer`，无第三方 PDF 引擎。

## 本版新增（P0 → P2）

**P0 可靠性**
- 写盘串行队列 + tmp/rename 原子替换：快速连续落笔不会被旧快照盖掉
- `onStop` 同步 flush，切后台 / 杀进程不丢最后一笔；写盘不再依赖会被 cancel 的协程
- 页面回收即从索引移除，撤销 / 清除 / 导入不会作用到废弃 View
- 内容指纹改为「长度 + 头 / 中 / 尾 64K」纯顺序采样，与文件来源无关
- 4 组 JVM 单测：几何裁剪、指纹、备份路径安全、全局撤销时间轴

**P1 手感与性能**
- 自由笔改增量段绘制（O(n) 而非 O(n²)）、低延迟预测墨迹、触控笔压感
- 橡皮抬手只局部重绘被扫过的矩形，不再重建整页位图
- 页面 / 缩略图位图缓存改为按字节限额；缩略图独立缓存
- 撤销升级为跨页、跨操作的全局时间轴

**P2 做题工作流**
- 套索：圈选笔迹后单指拖动、右下角柄缩放、单独删除
- 文字便签（点已有便签可改）、页面书签、最近卷子书架、页码跳转面板
- 批注分层：第一遍作答 / 订正两层，订正层可单独隐藏
- 笔迹烘焙进**新的 PDF 副本**：整本 / 当前页 / 总览多选页，原文件始终不动
- 导出与合成不再依赖已绑定的 View，回收页、后台导出都正确

**v2 已有**：横屏沉浸、5 色 3 档、贝塞尔平滑、荧光笔、直线/矩形/椭圆/箭头、
真裁剪橡皮、手掌抑制、仅触控笔、双指缩放平移、双指横滑与边缘翻页、
相邻页预渲染、题目/草稿对开、护眼 3 档 + 亮度、缩略图总览、
`.moye` 备份导入、PNG 导出、左右手切换、三指双击恢复工具条。

## 运行

Android Studio（Ladybug+，JDK 17）打开本目录，Sync 后 Run。
命令行：`./gradlew test assembleDebug`（`verify.sh` 封装了这两步）。
首次启动点中间的文件夹图标选择 PDF。

## 已知边界（如实说明）

- **没有在本环境实机编译**：当前环境只有 JDK 11、无 Android SDK、外网受限。
  工程已通过 XML / 资源引用 / 接口一致性 / 括号引号 / 错误包路径 / 占位代码 /
  功能落点的静态校验，但 `assembleDebug` 与真机横屏验收需要在你的机器上跑一次 `verify.sh`。
- **PDF 原生目录（Outline）不可用**：Android 系统 `PdfRenderer` 不暴露书签树。
  替代方案是「用户书签目录 + 页码跳转 + 书架」导航面板；本版没有伪造一个不可靠的 outline 解析器。
- 导出 PDF 是把页面烘焙成位图再装订（可打印、可交作业），成品里的题目文字不可再选中/搜索。
- 加密 / 扫描版 PDF 的渲染效果取决于系统 `PdfRenderer`。
- AGP / Gradle 版本若提示不一致，按 Android Studio 提示升级即可。

## 荣耀 10 兼容补丁（EMUI 8.1 / 9.1）

荣耀 10 = 麒麟 970、5.84" 2280×1080 19:9 刘海屏、出厂 Android 8.1 / EMUI 8.1，
官方最高 Android 9 / EMUI 9.1。以下三项已针对该机处理：

1. **导出 PNG 的运行时权限**：Android 9 及以下走 `MediaStore.insertImage`，
   需要 `WRITE_EXTERNAL_STORAGE` 动态授权。现在只在首次点「导出当前页图片」时申请，
   授权后自动续跑；未授权只给一个极短的提示，不弹说明文字。Android 10+ 走 MediaStore
   IS_PENDING，不需要权限。导出 PDF 走 SAF，全程不需要权限。
2. **横屏刘海**：Android 9 读 `DisplayCutout` 并显式设 SHORT_EDGES，行为可预测；
   华为「隐藏显示区域」开关打开时改设 NEVER 且不再重复补边；Android 8.1 无平台
   cutout，用华为私有 `HwNotchSizeUtil` 反射取真实刘海宽度并按旋转方向补边。
   工具条、底部条、左右边缘翻页热区、展开按钮同步平移。
3. **导出按内存降载**：按 `Runtime.maxMemory()` 分档 720 / 900 / 1240 px，
   页数越多再降一档，对开模式额外打折；单页高度上限同步收紧，避免麒麟 970
   上整本导出时 `PdfDocument` 累积位图 OOM。

**不需要启动页**：系统强制 SplashScreen 从 Android 12 起才有，荣耀 10 最高 Android 9，
因此未引入 `core-splashscreen`，点图标直接进主界面。

**别开「仅触控笔」**：荣耀 10 无主动式触控笔，开启后手指完全写不了。
系统级 palm 分类需要 Android 14，本机手掌抑制退化为触点面积判断，觉得别扭可关掉。

**真机验收补充**
  7. 首次点「导出当前页图片」应弹出一次存储授权，同意后相册里能看到 PNG
  8. 横屏旋转 0/90/180/270 四个方向，顶部工具按钮与左右翻页热区都不被刘海压住
  9. 系统设置里切换「隐藏显示区域」开关，工具条不应出现双份留白
  10. 连续导出 30 页以上 PDF 不闪退

## v5 竖屏可用与 UI 适配

原本锁 `userLandscape`，现在改为 `fullUser`：允许竖屏与两个横屏方向，
并继续尊重系统「旋转锁定」。v4 的 `configChanges` 保证旋转时不重建 Activity、
不跳回第 1 页，会话状态原样保留。

**先纠正一个说法**：荣耀 10 竖屏约 393dp 宽、829dp 高，A4 纸页能铺到
约 393×556dp；横屏时受 54+52dp 上下栏挤压，纸页只有约 203×287dp。
**竖屏的纸反而大得多**，瓶颈从来不是纸小，而是横向工具条和对开模式。

- **四边刘海安全区**：Android 9 读 `DisplayCutout` 的 left/top/right/bottom，
  竖屏时刘海在顶部，此前只取左右会压住顶栏；Android 8.1 私有
  `HwNotchSizeUtil` 补齐 0°/180° 上下边映射，并把避让深度修正为
  `getNotchSize()[1]`（刘海高），此前取 `[0]`（刘海宽）会大得离谱。
  `systemBars()` 已含刘海时用 `max` 合并，避免补两次。
- **栏高跟着安全区走**：顶/底栏高度 = 基准 50/48dp（横屏 54/52dp）
  + 状态栏/刘海 + 内边距；`pager` 留白、图形条与选区条的上边距、
  悬浮键位置全部由同一个 `applyChrome()` 同步，图标不会被 padding 裁掉。
- **竖屏工具条真正精简**：常驻只留「打开 / 5 色 / 笔 / 橡皮 / 撤销 / 更多」
  约 300dp，393dp 宽度下**不需要横向滚动**。收起的粗细、笔刷槽、荧光笔、
  重做全部搬进浮层：浮层首行加「荧光笔 / 重做」，第二行是完整的
  调色 + 粗细 + 4 个笔刷槽，功能一个不少、零文字。
- **悬浮键让位**：临时橡皮从右侧中部挪到底栏上方；展开按钮避开底部安全区；
  左右翻页热区 14dp → 10dp，少占纸页宽度。
- **对开自动降级**：竖屏下 `effectiveSpread` 为 false，只显示题目页；
  用户设置原样保留，转回横屏自动恢复。导出 PNG / PDF 同样按当前方向判定，
  竖屏不会出两张并排页面。
- 顺带修掉 v4 一处编译错误：`refreshUndoState()` 引用了从未声明的
  `::btnUndo` / `::btnRedo`，改为按 id 查找。

横屏布局与交互完全不变，仍是做题主场景。

**真机验收补充**
  17. 关闭旋转锁，竖着打开卷子应正常显示，顶栏不被荣耀 10 刘海压住
  18. 竖屏常驻工具条一屏放得下，不用横向滚动；浮层里能换粗细 / 存笔刷 / 荧光笔 / 重做
  19. 竖屏开启「题目与草稿对开」应只显示题目页，转回横屏自动恢复对开
  20. 竖屏导出 PNG 与 PDF 不应出现两张并排页面
  21. 旋转时纸页不被裁切、图形条不压住顶栏、悬浮键不挡题目

## P0–P2 横屏适配：左右不再空、隐藏栏不再留白

**先纠正一个物理限制**：竖版 PDF 在 19:9 横屏上，不裁切就不可能同时铺满
宽和高。原来按高度 fit，荣耀 10 横屏可用高约 253dp，A4 纸只剩约 179dp 宽
（屏宽的 22%），就是截图里中间那一长条。所以「全屏」拆成两种可选模式。

### P0 修掉的 bug
`toggleBars()` 只把顶/底栏设成 `GONE`，却没重算 `pager` 的上下 padding ——
`applyChrome()` 里一次性写死的 54/52dp 还占着，栏没了那 140dp 变成上下
大片空白，纸页却仍是 253dp 高。现在栏显隐统一走 `applyChrome()`：
隐藏时上下 padding 归零，`btnShow` / 悬浮橡皮 / 图形条 / 翻页热区同步，
并触发一次按新尺寸的重渲染（否则纸变大后仍是旧的低清位图）。

### P1 三种横屏显示模式（更多 → 三个图标，竖屏不显示）
- **适应屏幕 FIT**：整页 fit，原行为，页码语义完全不变
- **适应宽度 WIDTH**：纸页按可用宽度铺满，左右不再留白、字最大；
  纵向超出部分用**双指同向拖动**上下平移。单指仍照常写字，零新手势、
  零冲突：`ZoomHost` 在 `scale=1` 且 `panExtraY>0` 时放开纵向平移边界，
  抬手也不再把 `tx/ty` 清零
- **双页并排 DOUBLE**：相邻两页各占半宽，左右留白直接变成第二页；
  翻页一次走一组（两页），页码显示为 `3–4 / 15`。与「题目 / 草稿对开」
  互斥（双页优先，用户设置原样保留，切回来自动恢复）

**架构**：DOUBLE 下 ViewPager2 的一个 item 是「一组两页」，itemCount 减半，
组内主页 = `viewPos*2`、副页 = `viewPos*2+1`。这样每个逻辑页只有唯一一个
可写 InkView，不会与相邻 item 的预加载笔迹键撞车 —— 若一个 item 仍等于
一个逻辑页，副页 `p+1` 会和下一 item 的主页重复绑定同一 key，

## 竖屏适配 + 放大清晰 v15

**诊断**：竖屏 FIT 本来就是 1:1（1080px 纸 / raw 上限 1800px），未放大并不糊；
真实缺口是 v14 的分块入口写死「WIDTH 且未旋转」，竖屏完全没用上分块。
放大必糊的根因是 `ZoomHost` 用 `spreadRoot.scaleX/scaleY` 做 View 变换，
1080px 底图被插值到最多 4×；`InkView` 也是 View 尺寸位图缓冲，**笔迹一起糊**。
整页按 4× 重渲染需 4320×6112 ≈ 105MB/张，两层三缓冲直接 OOM，必须分块。

**架构：viewport 驱动，无 View 缩放**

新增每页独有的 `Viewport`（ViewPager2 同时有多页，用单例会串倍率）。
`ZoomHost` 只维护 scale / tx / ty 数值，不再对 `spreadRoot` 做
scaleX/scaleY/translation；子 View 在 `onDraw` 里按同一组数自绘：

```
s        = bucket(scale)                   // 1 / 1.5 / 2 / 3 / 4 档
lw, lh   = width*s, height*s               // 逻辑画布（放大后整页像素）
left     = width*(s-1)/2 - tx              // 可见窗口左上角
top      = height*(s-1)/2 - ty
canvas.translate(-left, -top)              // 之后都按逻辑坐标绘制
```

- **底图**：v14 的纵向条带升级成二维 400×400 网格块，
  `PdfRepo.renderTile()` 用 `A = lw / pageWidth` 的矩阵只渲染该块，

## 浏览模式 v16：手势全恢复 + 默认浏览 + 点击切做题

**用户报告**：点双箭头切到浏览模式后，上下滑动、任意手势放大缩小、
翻页全都不起作用。

**根因（两个叠加，不是各手势分别坏）**

1. `InkView.dispatchTouchEvent()` 在 `browseMode` 直接 `return false`；
   `TiledPageView` / `PageContainer` / `spreadRoot` / `ZoomHost` 都不消费
   `ACTION_DOWN`。Android 规则：**DOWN 无人消费，后续 MOVE /
   POINTER_DOWN / UP 不再派发给这棵 View 树** → `ZoomHost.handle()`
   连事件都收不到，双指缩放 / 上下平移 / 双指横滑翻页「一起失效」。
2. `ZoomHost` 在 `ACTION_DOWN` 无条件
   `requestDisallowInterceptTouchEvent(true)`，ViewPager2 靠
   `onInterceptTouchEvent` 拦横向滑动，被禁后单指翻页也没了。

**P0 修触摸链**

- 浏览模式由 `ZoomHost` 自己消费 `DOWN`，整条事件链恢复
- `disallow` 只在做题模式调用；浏览模式把横向拦截权还给 ViewPager2
- 多指开始才临时锁父级拦截（双指横滑翻页不被抢），结束恢复
- 清掉 `ACTION_POINTER_DOWN` 时的 `super.dispatchTouchEvent()` 重复分发；
  做题模式多指开始时给 InkView 补发 `ACTION_CANCEL` —— 否则第一指
  起的那一笔永远收不到 `UP`，会残留在 `live` 缓冲（顺手修掉的真 bug）
- `currentZoom` 是全局值、切页不重置 → `updatePagerInput()` 改按
  `PagesAdapter.zoomOf(当前页)` 判断；`onPageSelected` 也补一次刷新

**P1 单指上下滑（推荐口径）**

浏览模式且页面有纵向超出（`panExtraY>0` 或 `scale>1`）时，
单指纵向拖动 = 上下平移；横向仍交给 ViewPager2 翻页。
判定抽成 `GestureArbiter` 纯函数（纵向 > 阈值且 > 横向），
竖屏 FIT 无纵向超出时单指上下不产生动作、也不会误触。
双指同向拖动仍可用，两套并存。

**P2 默认浏览 + 两态**

- `UiState` 默认 `true`；`browseMigrated` 升级标记让老配置也回浏览。
  推荐口径「记住上次模式」：切到做题写进偏好，重开保持做题
- 按钮语义反转：**做题态高亮**；图标两态 —— 浏览态显示笔（点它去做题）、
  做题态显示页面横线 + 滑动箭头（点它回浏览），读屏两态描述，零文字
- 绘图按钮不再在浏览态悄悄切工具却画不上：**点任意绘图按钮直接
  切回做题并选中该工具**（保持可点击，比真禁用更顺一步到位）
- 悬浮橡皮在浏览态隐藏；若正处橡皮态切浏览则复位

> 一处取舍：绘图按钮没有设 `isEnabled=false`。真禁用会让点击彻底
> 没反应，与「默认浏览后天天要点」冲突；改成点击即退出浏览更符合
> 计划里「更顺，一步到位」的优先级，视觉仍用 0.4f 表示当前不可用。

**P3 验收**
  52. 默认打开就是浏览：单指左右翻页、上下滑（页面超出时）、双指缩放都生效
  53. 点笔图标切做题：单指写字落点准、双指缩放不留残笔、横向不被误翻页
  54. 再点回浏览：无残留笔迹、悬浮橡皮消失、翻页恢复
  55. 放大后翻到下一页仍可横向翻页；音量键/底栏箭头/进度条/边缘热区两态都通

## 统一返回栈与侧滑退出 v23

用户要求：**返回逻辑和手机返回一致，侧滑返回上一界面，连续侧滑两次退出**；
补充：**首页时也要侧滑两次，第一次侧滑进行提醒**。全做、按推荐。

**诊断：当前根本没有返回栈**

全工程 `onBackPressed` / `OnBackPressedDispatcher` / `OnBackInvokedCallback` /
`finish()` 命中均为 0 —— 系统返回键与侧滑走默认行为，**一次就退出**；而
「更多 → 返回书架首页」走 `showHome()` 只切界面、不结束 Activity。两条路径
不一致。

还有一个必须先绕开的坑：`targetSdk = 35`，Android 15 对 targetSdk≥35
**强制启用 OnBackInvoked、不可关闭**，直接覆写 `onBackPressed()` 在高版本
收不到事件。Manifest 原先也没写 `enableOnBackInvokedCallback`。

侧滑「不像手机」是三层叠加：
1. `edgeLeft/edgeRight` 贴屏幕左右边缘、`match_parent` 高，
   `attachEdge()` 在 `ACTION_DOWN` 就 `return true` 消费并锁定父级拦截 ——
   系统返回正是从这条边缘起手
2. v16 浏览态单指横滑交给 ViewPager2 翻页，边缘与中间同一动作结果不同
3. `hideSystemBars()` 在 API 26/28 用 `IMMERSIVE`（非 STICKY）+ 「栏一露出
   立刻重 hide」；legacy 沉浸下从边缘滑入会先显示系统栏并**消费这次滑动**，
   荣耀 10 / EMUI 8.1/9 上很可能就是「第一次侧滑没反应」的来源

第 3 条涉及厂商 ROM 手势实现，属静态推断，需真机确认；前两条是代码事实。

**口径：合并模型**

用户同时要求「连续两次退出」「首页也两次」「第一次提醒」，因此：
做题态第一次侧滑 = **返回上一界面（回首页）**，同时记为退出确认第一下并提醒；
首页第一次侧滑 = 提醒（不退出）；2s 窗口内第二次 = `finish()`。
这样从卷子里 / 从首页冷启动**都是两次退出**，且第一次都有提醒。

**P0 返回栈（`handleBack()` 优先级）**

`setupBackNavigation()` 用 `OnBackPressedDispatcher.addCallback`
（`androidx.activity:activity-ktx:1.9.3` 自动桥接 OnBackInvoked），
API 26–35 一套代码；Manifest 显式 `enableOnBackInvokedCallback="true"`。

1. 套索选区 active → `cancelSelection()`，重置确认计时
2. `barsHidden` → `toggleBars(false)` 恢复工具栏，重置确认计时
3. 做题态 → `goHome()`（`saveSessionNow()` + `showHome()`），记为第一下 + 提醒
4. 首页根 → 窗口内第二次 `finish()`，否则 `flash(back_exit_hint)` 提醒

`PopupWindow`（2 个，focusable）与 `AlertDialog`（8 个）是独立 Window，
系统自行 dismiss，dispatcher 不介入。`openingDocument`（SAF / 文档加载）
期间不接管。提醒文案「再侧滑一次退出墨页」是全 App 唯一一处提示文字，
由用户本轮明确要求；零动效、零其他说明小字。

**P1 让侧滑真的能触发**

- `edgeLeft/edgeRight` 从贴边内移 **24dp**（`translationX = safeL + dp(24)` /
  `-safeR - dp(24)`），屏幕最外侧留出没有任何 View 消费 `ACTION_DOWN` 的
  系统返回手势区；热区仍可点击翻页，只是不再贴边
- `attachEdge()` 删掉全部父级拦截锁定，横向裁决权还给系统 / ViewPager2
- API<30 的 `SYSTEM_UI_FLAG_IMMERSIVE` → **`IMMERSIVE_STICKY`**，避免首次
  边缘滑动被「先显示系统栏」吞掉；保留可见性监听器立刻重 hide，
  状态栏依旧不常驻（与 v14 的细微取舍见下方限制）
- 全程不调用 `setSystemGestureExclusionRects`（工程本来就没有）
- 中间区域横向滑仍翻页；边缘起手 = 返回，两者不重叠

**P2 配套**

`goHome()` 抽出，`handleBack()` 与「更多 → 返回书架首页」共用同一函数，
菜单路径不弹提醒；`goHome()` 先 `saveSessionNow()`，补上 v21 之后
「返回首页这一跳漏存逐页视口」的缺口。首页态不会误返回到已销毁的文档。

**P3 验收**

静态断言：无 `onBackPressed` 覆写、dispatcher 已注册、四级优先级、
2s 窗口、边缘热区不消费最外侧、无父级拦截锁定、STICKY、
Manifest 显式启用。`verify.sh` 补 4 条（共 69）。真机荣耀 10 验：
卷子里侧滑 → 回首页且记录仍在 → 再侧滑 → 退出；首页冷启动侧滑 1 → 提醒、
侧滑 2 → 退出、间隔超 2s 重新计；隐藏工具栏 / 选区 / 浮层逐级关闭；

**已知限制（如实说明）**

1. `IMMERSIVE_STICKY` 在部分 EMUI 上会让系统栏极短暂半透明露出后被
   监听器压回，与 v14「绝对不露」有细微取舍；换来的是首次侧滑不再被吞。
   真机若仍被吞，可进一步改为「只 FULLSCREEN、不 HIDE_NAVIGATION」。
2. Android 14+/15 预测式返回会在侧滑时显示「回桌面」预览，而第一级其实是
   App 内部切页，观感有轻微错位；系统动画，不影响实际行为。
3. 从卷子里退出需要「回首页 + 退出」两次，中间的提醒文案同时承担
   「已到根页」与「再滑退出」两重语义，这是为满足两次退出的合并口径。

## 竖屏上下滑浏览 v26

**诊断**：不是手势被抢，是竖屏根本没有「可上下移动的内容」。v19 的 FILL

于是 v16 那条单指纵向平移的开关 `canPan = panLimitY() > 0.5f` 恒 false，
上下 MOVE 只更新 `lastSingleY`；双指同向拖动的 `ty += dy` 也被 0 边界钳回。
横向 `panLimitX()>0` 归 ViewPager2，所以只剩左右翻页。

**P0 竖屏上下滑**：`applyPagerOrientation()` 把竖屏 ViewPager2 切到
`ORIENTATION_VERTICAL`，横屏保持 `HORIZONTAL`。跨页纵向滚动由系统
RecyclerView 原生接管，页面本身仍一屏完整、不被上下裁切，v19 铺满保住。

- 竖屏 1×：**上下滑 = 连续跟手浏览**（当前页推走、相邻页接上）
- **左右滑翻页保留**：VERTICAL 后横向不再触发 pager 滚动，由
  `GestureArbiter.isHorizontalFlip` 补一次离散翻页（`horizontalFlipDone`
  防重复）；1.2 倍方向比避免手写斜划误翻
- 放大态：`updatePagerInput()` 关掉 `isUserInputEnabled`，纵向自动回到
  ZoomHost 的页内平移；横屏 WIDTH 的 `panLimitY>0` 分支完全不回归
- 做题态：InkView 消费 DOWN，单指写字不受影响
- 切方向时保存并恢复 `currentItem`，不做平滑滚动避免闪帧

## 竖屏栏间铺满 · ChromeLayout 统一占位 v29

**用户口径**：有栏时文件铺满功能栏之间的区域；隐藏栏后铺满整个屏幕；
点「适应屏幕 / 适应宽度」也一样留白，要优化。

**实测（1080×2340 截图中央列采样）**：顶栏白 0–300px、米白 300–500px、
纸页 500–1980px（≈1480px）、米白 1980–2170px、底栏 2170–2340px。
栏间可用高 ≈1930px，纸页只占 77% —— 这是 **WIDTH 模式**按宽度铺满后的
页高，说明默认 FILL 根本没生效，而不是「铺满了还留白」。

**三条根因（代码事实）**

1. **假留白**：`setupInsets()` 已把 `sysTop/sysBottom` 硬置 0（状态栏彻底隐藏），
   但 `applyChrome()` 仍算 `cutTop = maxOf(sysTop, safeT)`，结果全等于刘海
   `safeInsetTop`；同一个值又进了 **顶栏高度 + 顶栏顶部 padding +
   `pager` paddingTop** 三处，屏幕上缘多出一条白带、内容区被压矮。
2. **页面居中**：`spreadRoot gravity=center`、`PageContainer center_vertical`
   三态共用；只要页高 < 可用高就垂直居中 → 上下米白。`toggleBars()` 只改
   `pager` padding、不改页面基准尺寸，隐藏栏后留白反而更宽。
3. **默认没进 FILL**：`currentFitMode()` 要求 `!landscape && fillScreen &&
   effectiveMode==WIDTH`；老配置里点过适应屏幕 / 适应宽度会留下
   `fillScreen=false + modeChosen=true`，或会话残留 FIT，于是退回 FIT/WIDTH，
   三态看起来一样。另外 `fillScale()` 把 cover 钳在 1.8x，宽幅页 / 大可用高
   时页高 < 可用高，也会留白。

**P0 去掉假留白**：新增纯 JVM `ChromeLayout.metrics()` 作为文档态栏占位
唯一出口。竖屏 `cutTop/cutBottom=0`（状态栏/导航栏已隐藏、不延伸进刘海区），
横屏保留 `safeL/safeR` 与 `cutBottom` 避让旋转后的刘海。`topBar` 高度回到
`50dp + 6dp`，图标在 38dp 内垂直居中；`pager padding` = 栏高，隐藏栏时归零。
首页 `homeHeader` / `homeStage` 仍保留原刘海避让，v22 不回归。

**P1 让铺满真铺满**
- `FitModeResolver`（纯 JVM）显式三态：竖屏 `fillScreen=true → FILL`；
  否则 FIT / WIDTH；横屏三模式一概不动。`currentFitMode()` 委托它。
- `PageContainer.fillScaleExact()` 严格 cover：`s = max(1, availH·ratio/availW)`
  且只受 8x 防御上限，**不再被 1.8x 钳制**。A4 竖页 → `h = 可用高`（有栏
  1935px / 隐藏栏 2340px），`w` 按比例横向略超出可平移；细长页 → `w = 可用宽`、
  纵向超出可拖；宽幅页 → 纵向严格铺满。任何比例都四边零留白。
  v19 的 `fillScale()` 与 `FillScreenTest` 原样保留。
- 竖屏 FILL / WIDTH 把 `spreadRoot` 与三个 `PageContainer` 改成 **顶部对齐**，
  不再居中；FIT 仍居中（用户主动选的整页 contain，唯一允许留白）。横屏不动。
- `loadPrefs()` 加 `fillV29Migrated` 一次性标记：老配置的
  `fillScreen=false / modeChosen=true` 强制回默认铺满，只迁一次，之后用户
  主动选的模式照常记住。**没有这一步，升级后仍是 WIDTH、留白依旧。**
- `PagesAdapter.relayoutForChrome()`：栏显隐后对三个容器 `requestLayout()`
  再 `refreshHostBounds()`。只调后者不够 —— fitMode 值没变时 setter 不会
  触发重新测量，FILL 页高会停在旧可用高。`toggleBars()` 另补缓存失效。

**P2 配套**：`shapeBar` / `selectionBar` / 悬浮橡皮 / 左下呼出按钮统一用
`ChromeMetrics`；分块按新尺寸重渲染（字仍 1:1 锐利）、笔迹归一化落点、

**三态口径（内容区 = 栏间 / 隐藏栏时 = 整屏）**
- 铺满屏幕 FILL：页高 = 可用高，上下零留白，左右超出双指横拖 ← **默认**

**已知限制**：FILL 严格 cover 会让宽幅页面横向裁切较多，想看整页请切

## 荣耀 10 顶部功能栏刘海遮挡修复 v30

**现象**：v29 之后，竖屏顶部功能栏的文件夹 / 色圈 / 笔 / 橡皮图标被刘海挖孔遮住。

**根因**：`setupInsets()` 在 API≥P 且用户没开「隐藏显示区域」时设置
`LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`，**窗口本来就画进刘海区**；
状态栏虽被 `hideSystemBars()` 隐藏，物理挖孔仍在屏幕顶部。v29 为修「同一刘海
高度被算进顶栏高 + 顶栏 padding + 阅读区三处」的重复留白，把竖屏 `cutTop`
一刀切归零 —— 顺带把必需的物理避让也删了，顶栏从 y=0 起、仅 18px 顶部
padding，图标正好落进挖孔区。

**修法（只算一次，不回退 v29）**

- `ChromeLayout.metrics()` 恢复 `cutTop = max(sysTop, safeT)`（竖屏横屏一致，
  `safeT` 来自 `DisplayCutout.safeInsetTop`，EMUI 8.1 走华为私有
  `HwNotchSizeUtil`；系统开「隐藏显示区域」时 `NotchCompat` 返回 0，无双份留白）。
- `barTop = baseTop + cutTop + gapTop` 是**容器总高**（白色背景延伸到刘海区），
  `topPaddingTop = cutTop + gapTop` 是**图标起始 y**，二者是包含关系，不是叠加。
  阅读区只按 `barTop` 扣一次，绝不重复压矮；`barTop - topPaddingTop = baseTop`
  恒定，图标可用高度不被刘海吃掉。
- 首页 `homeHeader` / `homeStage` 复用同一份 `cm.cutTop`，不再各算一套。
- **隐藏栏态**：顶栏消失但挖孔还在。`PdfViewportGeometry.contentInsets()`
  新增带默认值的 `hiddenSafeTop` 参数（默认 0，原调用与单测语义不变），
  传 `cm.hiddenPagerTop = cutTop`；纸页顶部让开物理刘海区，FILL 按新的
  可用高重新严格铺满。系统开了「隐藏显示区域」时该值为 0，仍是真·整屏。
- `cutBottom` 竖屏仍为 0（底部无刘海），横屏继续保留旋转后的左右 / 底部避让。

## v31 适应两态居中与放大铺满

**现象**：「适应屏幕 / 适应宽度」下页面贴在顶栏下、底部堆约 455px 米白（1080×2340

## v37 书写模式与套索解耦

**用户反馈**：「切换到书写模式时套索功能就自动打开了，我点击套索图标关闭套索

### 问题 A：切进书写模式自动进套索

## v41 · 套索选中从「全点包含」改为「碰到就中」

计划阶段三个推荐全部落地：**A 碰到就中** / **自动补弦并画出** /
**空选给轻反馈**。P0–P4 全做。

### 修复前为什么会「老是选不中」

`GeometryCore.markInside()` 要求一条笔迹的**每一个采样点**都在圈内，只要有一个点
露出去，整条直接作废；而且选 0 条时静默取消，没有任何反馈。叠加：

- 只判点不判线：长笔画横穿圈、但采样点在圈外，判不到；直线/矩形只有 2 个顶点也一样
- 圈画成 C 形时首末补弦，弦另一侧算圈外
- 少于 3 个采样点的圈直接全部作废（快划一下全丢）
- 笔迹正好压在圈线上算圈外
- 只算可见图层，隐藏图层被排除却不提示

橡皮是「碰到就中」，套索偏偏反过来，手感自然对不上。

### 实现

- **P0** `GeometryCore.markHitsLasso(m, poly, padX, padY)`：包围盒粗筛 →
  点在内 / 贴边 → 相邻采样点连成的线段穿过圈 → 整条选中。
  新加 `segmentsIntersect` / 各向异性 `distAniso` / `polyNearPoint` /
  `polyHitsSegment`。`padX` / `padY` 按两个方向分别归一化（2.5dp），
  避免 `width != height` 时容差被拉伸。相交与内外判定在仿射变换下不变，
  仍用归一化坐标，与 `Mark.pts` 同坐标系。
- **P1** 形状（LINE / RECT / OVAL / ARROW / NOTE）按包围盒矩形与圈相交判，
  与 `crop()` 的橡皮口径统一；自由笔按采样点 + 线段求交。
- **P2** `lassoHitPolygon()`：≥3 点原样（射线法与虚线 `close()` 共用同一条补弦），
  2 点扩成沿法线外扩的胶囊矩形，1 点扩成小方框 —— 快划一下也能选中附近笔迹。
  `contains()` 本来就是射线法奇偶规则，自交圈稳定。

## v45 · PDF 目录 / 文字缓存 / 扫描页 OCR

承接 v44（全文搜索修复与文档内查找）。三项一起落地：

### 1. PDF 自带目录
系统 `PdfRenderer` 不暴露目录，但应用已有自己的 PDF 解析器：`PdfLayoutDoc.outline()` 读 `/Outlines`，
支持直接目标数组、`/A << /S /GoTo >>`、命名目标（`/Dests` 字典与 `/Names` 名称树），
标题支持 UTF-16 / UTF-8 / PDFDocEncoding，防环、限深（12 层）、限量（3000 项）。
导航面板里新增「目录」区：缩进显示层级，点一下跳页，当前章节标成强调色；
没有目录的文档这一块不出现，面板与以前一致。导航面板尺寸改为跟屏幕走。

### 2. 文字缓存与预提取
`TextCache`：全文文字按内容指纹存到 `cacheDir/text-cache`（gzip，先写临时文件再改名，
最多 40 份 / 150MB，按最久未用淘汰）。文档打开稳定 3 秒后后台预提取，
之后点查找基本是秒出。全是空白（扫描件 / 加密 / 解析失败）不落盘，避免一次临时失败被缓存成「没有文字」。

### 3. 扫描页 OCR
- `OcrEngine`（唯一依赖 ML Kit 的文件）：`com.google.mlkit:text-recognition-chinese`，
  内置模型、离线、不需要 Google Play 服务。**这是应用第一个第三方依赖**，APK 会明显变大。
- `OcrLayoutBuilder`：把识别结果转成与 PDF 文字层同构的 `PageTextLayout`，
  所以命中高亮、页内选字、复制对扫描页同样可用（字框由元素外框按字数均分，选字边界会有轻微偏差）。
- `OcrCache`：按指纹落盘、每 4 页存一次，可断点续识。
- 入口：更多菜单里的「识别扫描页文字」；整本都没有文字层时，查找会第一次直接引导过来。
  识别期间保持亮屏，可随时停止，已识别的页保留。

### 验收与边界
- 新增纯 JVM 单测：PdfOutline 5 / TextCache 5 / OcrLayout 7（累计与 v44 一起 36 条在本地通过）。
- 目录解析另用 PyMuPDF 生成的带对象流 + 压缩的真实 PDF（含中文标题）验证过。
- **未实机编译**：ML Kit 依赖坐标、识别速度与效果、识别期间内存占用、目录面板布局都需要在真机和手动构建环境中确认。

## v46 · 批注导出为标准 PDF 注释

菜单「导出整本 PDF」现在会先问一句：

- **标准批注版**：保留原 PDF 的文字和矢量，把墨页批注写成标准 PDF 注释，WPS / Acrobat / 系统阅读器都能看到，也能继续编辑或删除。

### 做法
- `PdfAnnotWriter`：纯 JVM，在原文件末尾**追加增量更新**（原文件字节一个不动）：新注释 + 外观流 + 改写后的页对象（续上 `/Annots`）+ 新交叉引用，`/Prev` 指回旧的。原文件是交叉引用流就写流，是表就写表。
- 映射：手写→`Ink`，直线/箭头→`Line`，矩形→`Square`，椭圆→`Circle`，便签→`Text`，高亮/下划线/删除线→`Highlight/Underline/StrikeOut`（含 `QuadPoints`）。

- 只导出可见图层；变宽（压感）笔迹按平均线宽写成固定线宽。
- 加密、读不出页树、文件超过 24MB：自动退回图片版并提示。

### 边界
- 只支持**整本**；单页 / 选页要抽页，仍走图片版。
- 双页并排里右半页的批注（`d<页号>`）不写入。
- 便签在标准注释里简化为黄色小图标 + 文本内容（`/Contents`），不带墨页里的背景色块和字体样式。
- 验证：本地 JVM 跑通 18 条单测；`qpdf --check`、pypdf、poppler 渲染核对了 6 种构造（经典表 / 交叉引用流 / 页旋转 90° / 已有链接注释 / 间接 `/Annots` 数组 / 二次追加）。**APK 未编译**，需 CI 或真机确认。

## v46 · 阅读增强（自动裁白边 / 夜间 / 位置记忆）

### 自动裁白边怎么做

没有去改页面的坐标系——笔迹、文字层、批注导出全按整页归一化坐标，改了就牵一发动全身。
做法是**只动视口**：打开一页时在后台渲一张 240 像素宽的小图，找内容外框（`AutoCrop.findBounds`），
然后把缩放平移对准内容（`AutoCrop.plan` → `ZoomHost.fitContent`），等价于隐藏四周空白，笔迹照常落在原位置。

- 背景色取页面外圈最多的一档，米黄纸 / 深色底也认；孤立噪点不撑大外框；
  空白页、只有页码、内容几乎铺满整页的不裁。
- 内容宽度加两侧各 2% 留白撑满屏宽，最多放大 2.5 倍，倍率增益不足 8% 不动；内容上缘贴屏幕顶。
- 只对「适应宽度 / 铺满屏幕」的单页生效；「整页适应」、双页并排、题目 / 草稿对开、连续滚动都不做。
- 只作用于还没有记忆位置的页，且打开那一刻倍率仍是 1×（你没动手）才生效；裁出来的位置会照常记进每页阅读位置。
- 切换开关时会清掉内存里的逐页缩放记忆并重新绑定（不动笔迹和书签），这样开 / 关立刻看得到效果。
- 旋转后的页按旋转后的样子扫描；外框结果按「页 × 旋转」缓存，换文档作废。

验证：`AutoCropTest` 8 条（外框、彩色底、噪点、空白 / 满页 / 只有页码、居中与顶对齐的数学、倍率上限）本地 JVM 跑通；

## v46 · WebDAV 同步备份

在原有「备份批注 / 导入批注」（`.moye`，其实是 zip）之上加了一条云端通道：菜单里的「WebDAV 同步」。

- **上传备份**：把全部批注打成 `.moye`，PUT 到你填的文件夹里，文件名固定 `moye-backup.moye`，覆盖云端旧文件。
- **下载恢复**：GET 下来，先检查是不是 zip（防止服务器把登录页当 200 返回），再走和「导入批注」同一个对话框——
  合并 / 覆盖都行，而且和本地导入一样**可撤销**。
- 打开对话框时会顺手查一眼云端有没有备份（大小、修改时间）。

### 取舍

- `WebDavClient` 只用 JDK 的 `HttpURLConnection`，**没有新增依赖**。Android 的它不允许 PROPFIND / MKCOL，
  所以只用 PUT / GET / HEAD，**云端文件夹要事先建好**（坚果云、Nextcloud、群晖 / 威联通都在网页里建个文件夹即可）。
- **只允许 https**，地址里自带账号密码的也拒绝；不跟随重定向（PUT 重放不安全，直接报错让用户改成最终地址）。
  家里 NAS 只开 http 的用不了——要放开得改 `usesCleartextTraffic` / 网络安全配置，这是有意没做的。
- 认证是 Basic（坚果云等要用「应用密码」）。Digest 不支持。
- **密码不存明文**：`SecretBox` 用 Android Keystore 的不可导出 AES-GCM 密钥加密后再存。
  应用数据被系统自动备份、换机恢复后密文解不开，只会让你重输一次密码，不会把密码带出设备。
- **新增 `INTERNET` 权限**——这是墨页第一次声明联网权限。只有用户在这个对话框里点上传 / 下载（和打开对话框时的一次查询）才会发请求，别处不联网。
- 同步是「手动上传 / 手动恢复」，不是实时双向合并：多设备同时改会以最后一次上传为准，恢复时可选合并。

验证：`WebDavTest` 8 条本地 JVM 通过——用 JDK 内置 `HttpServer` 起了个假 WebDAV（首次 201 / 覆盖 204、404、Basic 预认证、401、302 不跟随、非 zip 拒收、连不上、地址规则）。
`SecretBox`（Keystore）、对话框与菜单接线**未编译**，待 CI / 真机。

## v46 · 做题手感：按住拉直 / 规整图形、触控笔侧键橡皮

### 按住拉直 / 规整图形
画一条线或一个圈，**笔停住不抬**约 0.55 秒，就自动变成标准直线 / 椭圆（手感类似系统备忘录）：

- 识别在 `ShapeSnap`（纯 JVM）：
  - 直线：弦长 ≥ 路径长的 88%，且所有点离弦不超过弦长的 7%；±4° 内摆成水平 / 竖直（划线、下划线最常用）。
  - 椭圆：基本闭合、长宽都 ≥ 40px、点都贴着外接椭圆（平均偏差 ≤ 18%，最大 ≤ 35%）、角度绕了 ≥ 85% 一整圈；
    长宽相差 12% 内当正圆。方框、没画完的弧、来回描的线、波浪线、手写字都**不会**被吸附。
- 吸附成直线后笔不抬可以继续拖动端点；吸附成椭圆后形状固定。
- 吸附时轻震一下（`CLOCK_TICK`）。笔离开锚点 6dp 以内的抖动不算「动了」，不会反复重新计时。
- 菜单里有「按住拉直 / 规整图形」开关，默认开。图形工具（直线 / 矩形 / 椭圆 / 箭头）本来就是规整的，不受影响。
- 吸附产物就是普通的 `LINE` / `OVAL` Mark，撤销、导出标准 PDF 注释都照常。

### 手指偏移：先瞄准、再落笔（v48）

## v49 · 图形吸附：更多图形、更宽容

**问题**：吸附时灵时不灵，而且只有直线和圆。原因：`ShapeSnap.detect` 只认直线和椭圆；
椭圆的判定又很严（首尾几乎要封口、最差一点偏差不能超过 0.35、要绕满 85% 的圈），
手画稍微有点歪、有尾巴就过不了；长方形的角点偏差一定超标，所以永远识别不出来。

**识别（`ShapeSnap`，纯 JVM）**
- 闭合图形先等间距重采样（160 点），不再依赖手速 / 采样密度。
- 三种模型择优：椭圆（径向偏差均值 + p90，容忍一小段出头）、三角形、四边形；
  多边形用「离重心最远点 → 离它最远点 → 离连线最远点」找初始顶点，再按边归属点集拟合直线、相邻直线求交精修顶点；
  误差统一除以图形大小后比较，三角形在 1.5 倍误差内优先于四边形。
- 凸性、内角范围、每条边的笔迹覆盖（按边长折算，细长长方形的短边不会被卡掉）都要满足，避免把 V / Z / L 之类吸成图形。
- 四边形的四条边都在 ±16° 内横平竖直、四个角近似直角 → 摆正成长方形（长宽差 12% 内取正方形）；更斜的保留成多边形。
- 闭合判定放宽：首尾距离 ≤ 图形尺寸 30% 且 ≤ 路径长 14%；绕行角度 ≥ 80%。

**接入**
- 按住吸附：直线 / 椭圆 / 长方形 / 正方形照原来的图形；三角形 / 斜四边形保存为加密后的闭合折线（自由笔迹），
  橡皮、套索、移动、导出都不用改。
- 抬笔自动吸附（文字吸附开启时）：框字的长方形贴成刚好框住文字的矩形（`TextSnap.pickRect`）；
  压在文字上的三角形 / 斜四边形规整成干净折线；原有的下划线 / 高亮 / 圈字不变。
- 不压在文字上的图形仍然是「按住不动」才吸附，抬笔不会擅自改你随手画的东西。

**验证**：用模拟手画笔迹（抖动、圆角、缺口、出头、歪斜）每类 400 条反复验证：椭圆 98–100%、长方形 94–100%、
正方形 / 三角形 / 斜四边形 99–100%；Z / S / V / N / L / 螺旋 / 半圈 / 来回描等误吸 ≤ 1%。
手感阈值（`ShapeSnap` 里的 0.055 / 0.11 / ±16° 等）需真机用手指实际画几遍再微调。

### 图形 / 直线识别放宽（v50）
手画的圆被认成四边形、三角形，有的圆 / 长方形 / 三角形 / 直线又认不出来——按你说的「有这个形就行，不用画得特别规整」改了：

- **圆 vs 多边形**：以前靠「拟合误差谁小」来比，可圆也很像四边形，所以近一半的圆被判成多边形。现在先看**有没有明显拐角**：直边占三成以上（或多边形拟合得非常贴）才认多边形，圆几乎处处在转，认圆。
- **斜着画的椭圆 / 圆**：支持倾斜，落成光滑的斜椭圆（不再变成菱形）。
- **没封口、多画一截、起伏**：封口放到首尾距离 ≤ 路径的 25%，绕圈 ≥ 78% 就算；三角形内角放到 12°~150°，四边形 35°~155°；多边形拟合容差放宽。
- **直线**：弦长 ≥ 路径的 80%，弯度到 14% 都算直线；两头有小勾的去掉两头再试。
- **文字吸附对不上字时**：压在文字上的直线 / 圈 / 框，退一步规整成干净的直线 / 椭圆 / 矩形，不再原样留着；下划线容许歪 18°、画得比字低到 0.9 个字高。
- 用仿手画模拟（带起伏、抖动、没封口、倾斜）每类 400 笔测：圆 98%、斜四边形 100%、长方形 99.5%、三角形 98%、直线 99.8%（修改前：圆约 52%，直线 48.5%）。真手写比模拟更乱，阈值还要真机上看。
- 还没做：没有文字层的扫描页（没做 OCR）不吸附；要的话可以另开「任何位置都规整图形」的开关。

### 圈字更准、不变大（v51）
你说：识别还会认成别的图形，圈圈画画都是一笔完成；识别后图形变大；圈字要准，不能盖住字、也不能多圈字。
