# 墨页

v3 · 安卓原生（Kotlin）横屏 PDF 阅读 / 书写应用。系统 `PdfRenderer`，无第三方 PDF 引擎。

## 本版新增（P0 → P2）

**P0 可靠性**
- 写盘串行队列 + tmp/rename 原子替换：快速连续落笔不会被旧快照盖掉
- `onStop` 同步 flush，切后台 / 杀进程不丢最后一笔；写盘不再依赖会被 cancel 的协程
- 页面回收即从索引移除，撤销 / 清除 / 导入不会作用到废弃 View
- 内容指纹改为「长度 + 头 / 中 / 尾 64K」纯顺序采样，与文件来源无关
- 4 组 JVM 单测：几何裁剪、指纹、备份路径安全、全局撤销时间轴

**P1 手感与性能**
- 自由笔改增量段绘制（O(n) 而非 O(n²)）、低延迟预测墨迹、触控笔压感
- 橡皮抬手只局部重绘被扫过的矩形，不再重建整页位图
- 页面 / 缩略图位图缓存改为按字节限额；缩略图独立缓存
- 撤销升级为跨页、跨操作的全局时间轴

**P2 做题工作流**
- 套索：圈选笔迹后单指拖动、右下角柄缩放、单独删除
- 文字便签（点已有便签可改）、页面书签、最近卷子书架、页码跳转面板
- 批注分层：第一遍作答 / 订正两层，订正层可单独隐藏
- 笔迹烘焙进**新的 PDF 副本**：整本 / 当前页 / 总览多选页，原文件始终不动
- 导出与合成不再依赖已绑定的 View，回收页、后台导出都正确

**v2 已有**：横屏沉浸、5 色 3 档、贝塞尔平滑、荧光笔、直线/矩形/椭圆/箭头、
真裁剪橡皮、手掌抑制、仅触控笔、双指缩放平移、双指横滑与边缘翻页、
相邻页预渲染、题目/草稿对开、护眼 3 档 + 亮度、缩略图总览、
`.moye` 备份导入、PNG 导出、左右手切换、三指双击恢复工具条。

## 运行

Android Studio（Ladybug+，JDK 17）打开本目录，Sync 后 Run。
命令行：`./gradlew test assembleDebug`（`verify.sh` 封装了这两步）。
首次启动点中间的文件夹图标选择 PDF。

## 已知边界（如实说明）

- **没有在本环境实机编译**：当前环境只有 JDK 11、无 Android SDK、外网受限。
  工程已通过 XML / 资源引用 / 接口一致性 / 括号引号 / 错误包路径 / 占位代码 /
  功能落点的静态校验，但 `assembleDebug` 与真机横屏验收需要在你的机器上跑一次 `verify.sh`。
- **PDF 原生目录（Outline）不可用**：Android 系统 `PdfRenderer` 不暴露书签树。
  替代方案是「用户书签目录 + 页码跳转 + 书架」导航面板；本版没有伪造一个不可靠的 outline 解析器。
- 导出 PDF 是把页面烘焙成位图再装订（可打印、可交作业），成品里的题目文字不可再选中/搜索。
- 加密 / 扫描版 PDF 的渲染效果取决于系统 `PdfRenderer`。
- AGP / Gradle 版本若提示不一致，按 Android Studio 提示升级即可。

## 荣耀 10 兼容补丁（EMUI 8.1 / 9.1）

荣耀 10 = 麒麟 970、5.84" 2280×1080 19:9 刘海屏、出厂 Android 8.1 / EMUI 8.1，
官方最高 Android 9 / EMUI 9.1。以下三项已针对该机处理：

1. **导出 PNG 的运行时权限**：Android 9 及以下走 `MediaStore.insertImage`，
   需要 `WRITE_EXTERNAL_STORAGE` 动态授权。现在只在首次点「导出当前页图片」时申请，
   授权后自动续跑；未授权只给一个极短的提示，不弹说明文字。Android 10+ 走 MediaStore
   IS_PENDING，不需要权限。导出 PDF 走 SAF，全程不需要权限。
2. **横屏刘海**：Android 9 读 `DisplayCutout` 并显式设 SHORT_EDGES，行为可预测；
   华为「隐藏显示区域」开关打开时改设 NEVER 且不再重复补边；Android 8.1 无平台
   cutout，用华为私有 `HwNotchSizeUtil` 反射取真实刘海宽度并按旋转方向补边。
   工具条、底部条、左右边缘翻页热区、展开按钮同步平移。
3. **导出按内存降载**：按 `Runtime.maxMemory()` 分档 720 / 900 / 1240 px，
   页数越多再降一档，对开模式额外打折；单页高度上限同步收紧，避免麒麟 970
   上整本导出时 `PdfDocument` 累积位图 OOM。

**不需要启动页**：系统强制 SplashScreen 从 Android 12 起才有，荣耀 10 最高 Android 9，
因此未引入 `core-splashscreen`，点图标直接进主界面。

**别开「仅触控笔」**：荣耀 10 无主动式触控笔，开启后手指完全写不了。
系统级 palm 分类需要 Android 14，本机手掌抑制退化为触点面积判断，觉得别扭可关掉。

**真机验收补充**
  7. 首次点「导出当前页图片」应弹出一次存储授权，同意后相册里能看到 PNG
  8. 横屏旋转 0/90/180/270 四个方向，顶部工具按钮与左右翻页热区都不被刘海压住
  9. 系统设置里切换「隐藏显示区域」开关，工具条不应出现双份留白
  10. 连续导出 30 页以上 PDF 不闪退

## v5 竖屏可用与 UI 适配

原本锁 `userLandscape`，现在改为 `fullUser`：允许竖屏与两个横屏方向，
并继续尊重系统「旋转锁定」。v4 的 `configChanges` 保证旋转时不重建 Activity、
不跳回第 1 页，会话状态原样保留。

**先纠正一个说法**：荣耀 10 竖屏约 393dp 宽、829dp 高，A4 纸页能铺到
约 393×556dp；横屏时受 54+52dp 上下栏挤压，纸页只有约 203×287dp。
**竖屏的纸反而大得多**，瓶颈从来不是纸小，而是横向工具条和对开模式。

- **四边刘海安全区**：Android 9 读 `DisplayCutout` 的 left/top/right/bottom，
  竖屏时刘海在顶部，此前只取左右会压住顶栏；Android 8.1 私有
  `HwNotchSizeUtil` 补齐 0°/180° 上下边映射，并把避让深度修正为
  `getNotchSize()[1]`（刘海高），此前取 `[0]`（刘海宽）会大得离谱。
  `systemBars()` 已含刘海时用 `max` 合并，避免补两次。
- **栏高跟着安全区走**：顶/底栏高度 = 基准 50/48dp（横屏 54/52dp）
  + 状态栏/刘海 + 内边距；`pager` 留白、图形条与选区条的上边距、
  悬浮键位置全部由同一个 `applyChrome()` 同步，图标不会被 padding 裁掉。
- **竖屏工具条真正精简**：常驻只留「打开 / 5 色 / 笔 / 橡皮 / 撤销 / 更多」
  约 300dp，393dp 宽度下**不需要横向滚动**。收起的粗细、笔刷槽、荧光笔、
  重做全部搬进浮层：浮层首行加「荧光笔 / 重做」，第二行是完整的
  调色 + 粗细 + 4 个笔刷槽，功能一个不少、零文字。
- **悬浮键让位**：临时橡皮从右侧中部挪到底栏上方；展开按钮避开底部安全区；
  左右翻页热区 14dp → 10dp，少占纸页宽度。
- **对开自动降级**：竖屏下 `effectiveSpread` 为 false，只显示题目页；
  用户设置原样保留，转回横屏自动恢复。导出 PNG / PDF 同样按当前方向判定，
  竖屏不会出两张并排页面。
- 顺带修掉 v4 一处编译错误：`refreshUndoState()` 引用了从未声明的
  `::btnUndo` / `::btnRedo`，改为按 id 查找。

横屏布局与交互完全不变，仍是做题主场景。

**真机验收补充**
  17. 关闭旋转锁，竖着打开卷子应正常显示，顶栏不被荣耀 10 刘海压住
  18. 竖屏常驻工具条一屏放得下，不用横向滚动；浮层里能换粗细 / 存笔刷 / 荧光笔 / 重做
  19. 竖屏开启「题目与草稿对开」应只显示题目页，转回横屏自动恢复对开
  20. 竖屏导出 PNG 与 PDF 不应出现两张并排页面
  21. 旋转时纸页不被裁切、图形条不压住顶栏、悬浮键不挡题目

## P0–P2 横屏适配：左右不再空、隐藏栏不再留白

**先纠正一个物理限制**：竖版 PDF 在 19:9 横屏上，不裁切就不可能同时铺满
宽和高。原来按高度 fit，荣耀 10 横屏可用高约 253dp，A4 纸只剩约 179dp 宽
（屏宽的 22%），就是截图里中间那一长条。所以「全屏」拆成两种可选模式。

### P0 修掉的 bug
`toggleBars()` 只把顶/底栏设成 `GONE`，却没重算 `pager` 的上下 padding ——
`applyChrome()` 里一次性写死的 54/52dp 还占着，栏没了那 140dp 变成上下
大片空白，纸页却仍是 253dp 高。现在栏显隐统一走 `applyChrome()`：
隐藏时上下 padding 归零，`btnShow` / 悬浮橡皮 / 图形条 / 翻页热区同步，
并触发一次按新尺寸的重渲染（否则纸变大后仍是旧的低清位图）。

### P1 三种横屏显示模式（更多 → 三个图标，竖屏不显示）
- **适应屏幕 FIT**：整页 fit，原行为，页码语义完全不变
- **适应宽度 WIDTH**：纸页按可用宽度铺满，左右不再留白、字最大；
  纵向超出部分用**双指同向拖动**上下平移。单指仍照常写字，零新手势、
  零冲突：`ZoomHost` 在 `scale=1` 且 `panExtraY>0` 时放开纵向平移边界，
  抬手也不再把 `tx/ty` 清零
- **双页并排 DOUBLE**：相邻两页各占半宽，左右留白直接变成第二页；
  翻页一次走一组（两页），页码显示为 `3–4 / 15`。与「题目 / 草稿对开」
  互斥（双页优先，用户设置原样保留，切回来自动恢复）

**架构**：DOUBLE 下 ViewPager2 的一个 item 是「一组两页」，itemCount 减半，
组内主页 = `viewPos*2`、副页 = `viewPos*2+1`。这样每个逻辑页只有唯一一个
可写 InkView，不会与相邻 item 的预加载笔迹键撞车 —— 若一个 item 仍等于
一个逻辑页，副页 `p+1` 会和下一 item 的主页重复绑定同一 key，

## 竖屏适配 + 放大清晰 v15

**诊断**：竖屏 FIT 本来就是 1:1（1080px 纸 / raw 上限 1800px），未放大并不糊；
真实缺口是 v14 的分块入口写死「WIDTH 且未旋转」，竖屏完全没用上分块。
放大必糊的根因是 `ZoomHost` 用 `spreadRoot.scaleX/scaleY` 做 View 变换，
1080px 底图被插值到最多 4×；`InkView` 也是 View 尺寸位图缓冲，**笔迹一起糊**。
整页按 4× 重渲染需 4320×6112 ≈ 105MB/张，两层三缓冲直接 OOM，必须分块。

**架构：viewport 驱动，无 View 缩放**

新增每页独有的 `Viewport`（ViewPager2 同时有多页，用单例会串倍率）。
`ZoomHost` 只维护 scale / tx / ty 数值，不再对 `spreadRoot` 做
scaleX/scaleY/translation；子 View 在 `onDraw` 里按同一组数自绘：

```
s        = bucket(scale)                   // 1 / 1.5 / 2 / 3 / 4 档
lw, lh   = width*s, height*s               // 逻辑画布（放大后整页像素）
left     = width*(s-1)/2 - tx              // 可见窗口左上角
top      = height*(s-1)/2 - ty
canvas.translate(-left, -top)              // 之后都按逻辑坐标绘制
```

- **底图**：v14 的纵向条带升级成二维 400×400 网格块，
  `PdfRepo.renderTile()` 用 `A = lw / pageWidth` 的矩阵只渲染该块，
  位图分辨率 = 设备像素 1:1，放大不插值。可见窗口恒为 `width×height`，
  **块数不随倍率增长，4× 不多吃内存**；key 带 bucket，档内平移只换可见块、不闪。

  × `(lw,lh)` **矢量直绘**，bbox 与可见窗粗筛，不再放大位图缓冲；
  `s=1` 保留原增量绘制 / 预测墨迹 / 橡皮局部重绘链路，一点不改。
  正在写的一笔仍走局部位图（略糊），抬手并入 marks 后即锐利。
- **两层对齐**：题目底图与笔迹读同一个 `Viewport`，同一组
  `(lw,lh,left,top)`，放大后落点不偏。

**P0 竖屏补齐**

- 分块入口放宽为「所有未旋转页」：竖屏 FIT、横屏 WIDTH、双页并排都走 1:1；
