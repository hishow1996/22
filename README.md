# 墨页

v3 · 安卓原生（Kotlin）横屏 PDF 阅读 / 书写应用。系统 `PdfRenderer`，无第三方 PDF 引擎。

## 本版新增（P0 → P2）

**P0 可靠性**
- 写盘串行队列 + tmp/rename 原子替换：快速连续落笔不会被旧快照盖掉
- `onStop` 同步 flush，切后台 / 杀进程不丢最后一笔；写盘不再依赖会被 cancel 的协程
- 页面回收即从索引移除，撤销 / 清除 / 导入不会作用到废弃 View
- 内容指纹改为「长度 + 头 / 中 / 尾 64K」纯顺序采样，与文件来源无关
- 4 组 JVM 单测：几何裁剪、指纹、备份路径安全、全局撤销时间轴

**P1 手感与性能**
- 自由笔改增量段绘制（O(n) 而非 O(n²)）、低延迟预测墨迹、触控笔压感
- 橡皮抬手只局部重绘被扫过的矩形，不再重建整页位图
- 页面 / 缩略图位图缓存改为按字节限额；缩略图独立缓存
- 撤销升级为跨页、跨操作的全局时间轴

**P2 做题工作流**
- 套索：圈选笔迹后单指拖动、右下角柄缩放、单独删除
- 文字便签（点已有便签可改）、页面书签、最近卷子书架、页码跳转面板
- 批注分层：第一遍作答 / 订正两层，订正层可单独隐藏
- 笔迹烘焙进**新的 PDF 副本**：整本 / 当前页 / 总览多选页，原文件始终不动
- 导出与合成不再依赖已绑定的 View，回收页、后台导出都正确

**v2 已有**：横屏沉浸、5 色 3 档、贝塞尔平滑、荧光笔、直线/矩形/椭圆/箭头、
真裁剪橡皮、手掌抑制、仅触控笔、双指缩放平移、双指横滑与边缘翻页、
相邻页预渲染、题目/草稿对开、护眼 3 档 + 亮度、缩略图总览、
`.moye` 备份导入、PNG 导出、左右手切换、三指双击恢复工具条。

## 运行

Android Studio（Ladybug+，JDK 17）打开本目录，Sync 后 Run。
命令行：`./gradlew test assembleDebug`（`verify.sh` 封装了这两步）。
首次启动点中间的文件夹图标选择 PDF。

## 已知边界（如实说明）

- **没有在本环境实机编译**：当前环境只有 JDK 11、无 Android SDK、外网受限。
  工程已通过 XML / 资源引用 / 接口一致性 / 括号引号 / 错误包路径 / 占位代码 /
  功能落点的静态校验，但 `assembleDebug` 与真机横屏验收需要在你的机器上跑一次 `verify.sh`。
- **PDF 原生目录（Outline）不可用**：Android 系统 `PdfRenderer` 不暴露书签树。
  替代方案是「用户书签目录 + 页码跳转 + 书架」导航面板；本版没有伪造一个不可靠的 outline 解析器。
- 导出 PDF 是把页面烘焙成位图再装订（可打印、可交作业），成品里的题目文字不可再选中/搜索。
- 加密 / 扫描版 PDF 的渲染效果取决于系统 `PdfRenderer`。
- AGP / Gradle 版本若提示不一致，按 Android Studio 提示升级即可。

## 荣耀 10 兼容补丁（EMUI 8.1 / 9.1）

荣耀 10 = 麒麟 970、5.84" 2280×1080 19:9 刘海屏、出厂 Android 8.1 / EMUI 8.1，
官方最高 Android 9 / EMUI 9.1。以下三项已针对该机处理：

1. **导出 PNG 的运行时权限**：Android 9 及以下走 `MediaStore.insertImage`，
   需要 `WRITE_EXTERNAL_STORAGE` 动态授权。现在只在首次点「导出当前页图片」时申请，
   授权后自动续跑；未授权只给一个极短的提示，不弹说明文字。Android 10+ 走 MediaStore
   IS_PENDING，不需要权限。导出 PDF 走 SAF，全程不需要权限。
2. **横屏刘海**：Android 9 读 `DisplayCutout` 并显式设 SHORT_EDGES，行为可预测；
   华为「隐藏显示区域」开关打开时改设 NEVER 且不再重复补边；Android 8.1 无平台
   cutout，用华为私有 `HwNotchSizeUtil` 反射取真实刘海宽度并按旋转方向补边。
   工具条、底部条、左右边缘翻页热区、展开按钮同步平移。
3. **导出按内存降载**：按 `Runtime.maxMemory()` 分档 720 / 900 / 1240 px，
   页数越多再降一档，对开模式额外打折；单页高度上限同步收紧，避免麒麟 970
   上整本导出时 `PdfDocument` 累积位图 OOM。

**不需要启动页**：系统强制 SplashScreen 从 Android 12 起才有，荣耀 10 最高 Android 9，
因此未引入 `core-splashscreen`，点图标直接进主界面。

**别开「仅触控笔」**：荣耀 10 无主动式触控笔，开启后手指完全写不了。
系统级 palm 分类需要 Android 14，本机手掌抑制退化为触点面积判断，觉得别扭可关掉。

**真机验收补充**
  7. 首次点「导出当前页图片」应弹出一次存储授权，同意后相册里能看到 PNG
  8. 横屏旋转 0/90/180/270 四个方向，顶部工具按钮与左右翻页热区都不被刘海压住
  9. 系统设置里切换「隐藏显示区域」开关，工具条不应出现双份留白
  10. 连续导出 30 页以上 PDF 不闪退

## v5 竖屏可用与 UI 适配

原本锁 `userLandscape`，现在改为 `fullUser`：允许竖屏与两个横屏方向，
并继续尊重系统「旋转锁定」。v4 的 `configChanges` 保证旋转时不重建 Activity、
不跳回第 1 页，会话状态原样保留。

**先纠正一个说法**：荣耀 10 竖屏约 393dp 宽、829dp 高，A4 纸页能铺到
约 393×556dp；横屏时受 54+52dp 上下栏挤压，纸页只有约 203×287dp。
**竖屏的纸反而大得多**，瓶颈从来不是纸小，而是横向工具条和对开模式。

- **四边刘海安全区**：Android 9 读 `DisplayCutout` 的 left/top/right/bottom，
  竖屏时刘海在顶部，此前只取左右会压住顶栏；Android 8.1 私有
  `HwNotchSizeUtil` 补齐 0°/180° 上下边映射，并把避让深度修正为
  `getNotchSize()[1]`（刘海高），此前取 `[0]`（刘海宽）会大得离谱。
  `systemBars()` 已含刘海时用 `max` 合并，避免补两次。
- **栏高跟着安全区走**：顶/底栏高度 = 基准 50/48dp（横屏 54/52dp）
  + 状态栏/刘海 + 内边距；`pager` 留白、图形条与选区条的上边距、
  悬浮键位置全部由同一个 `applyChrome()` 同步，图标不会被 padding 裁掉。
- **竖屏工具条真正精简**：常驻只留「打开 / 5 色 / 笔 / 橡皮 / 撤销 / 更多」
  约 300dp，393dp 宽度下**不需要横向滚动**。收起的粗细、笔刷槽、荧光笔、
  重做全部搬进浮层：浮层首行加「荧光笔 / 重做」，第二行是完整的
  调色 + 粗细 + 4 个笔刷槽，功能一个不少、零文字。
- **悬浮键让位**：临时橡皮从右侧中部挪到底栏上方；展开按钮避开底部安全区；
  左右翻页热区 14dp → 10dp，少占纸页宽度。
- **对开自动降级**：竖屏下 `effectiveSpread` 为 false，只显示题目页；
  用户设置原样保留，转回横屏自动恢复。导出 PNG / PDF 同样按当前方向判定，
  竖屏不会出两张并排页面。
- 顺带修掉 v4 一处编译错误：`refreshUndoState()` 引用了从未声明的
  `::btnUndo` / `::btnRedo`，改为按 id 查找。

横屏布局与交互完全不变，仍是做题主场景。

**真机验收补充**
  17. 关闭旋转锁，竖着打开卷子应正常显示，顶栏不被荣耀 10 刘海压住
  18. 竖屏常驻工具条一屏放得下，不用横向滚动；浮层里能换粗细 / 存笔刷 / 荧光笔 / 重做
  19. 竖屏开启「题目与草稿对开」应只显示题目页，转回横屏自动恢复对开
  20. 竖屏导出 PNG 与 PDF 不应出现两张并排页面
  21. 旋转时纸页不被裁切、图形条不压住顶栏、悬浮键不挡题目

## P0–P2 横屏适配：左右不再空、隐藏栏不再留白

**先纠正一个物理限制**：竖版 PDF 在 19:9 横屏上，不裁切就不可能同时铺满
宽和高。原来按高度 fit，荣耀 10 横屏可用高约 253dp，A4 纸只剩约 179dp 宽
（屏宽的 22%），就是截图里中间那一长条。所以「全屏」拆成两种可选模式。

### P0 修掉的 bug
`toggleBars()` 只把顶/底栏设成 `GONE`，却没重算 `pager` 的上下 padding ——
`applyChrome()` 里一次性写死的 54/52dp 还占着，栏没了那 140dp 变成上下
大片空白，纸页却仍是 253dp 高。现在栏显隐统一走 `applyChrome()`：
隐藏时上下 padding 归零，`btnShow` / 悬浮橡皮 / 图形条 / 翻页热区同步，
并触发一次按新尺寸的重渲染（否则纸变大后仍是旧的低清位图）。

### P1 三种横屏显示模式（更多 → 三个图标，竖屏不显示）
- **适应屏幕 FIT**：整页 fit，原行为，页码语义完全不变
- **适应宽度 WIDTH**：纸页按可用宽度铺满，左右不再留白、字最大；
  纵向超出部分用**双指同向拖动**上下平移。单指仍照常写字，零新手势、
  零冲突：`ZoomHost` 在 `scale=1` 且 `panExtraY>0` 时放开纵向平移边界，
  抬手也不再把 `tx/ty` 清零
- **双页并排 DOUBLE**：相邻两页各占半宽，左右留白直接变成第二页；
  翻页一次走一组（两页），页码显示为 `3–4 / 15`。与「题目 / 草稿对开」
  互斥（双页优先，用户设置原样保留，切回来自动恢复）

**架构**：DOUBLE 下 ViewPager2 的一个 item 是「一组两页」，itemCount 减半，
组内主页 = `viewPos*2`、副页 = `viewPos*2+1`。这样每个逻辑页只有唯一一个
可写 InkView，不会与相邻 item 的预加载笔迹键撞车 —— 若一个 item 仍等于
一个逻辑页，副页 `p+1` 会和下一 item 的主页重复绑定同一 key，

## 竖屏适配 + 放大清晰 v15

**诊断**：竖屏 FIT 本来就是 1:1（1080px 纸 / raw 上限 1800px），未放大并不糊；
真实缺口是 v14 的分块入口写死「WIDTH 且未旋转」，竖屏完全没用上分块。
放大必糊的根因是 `ZoomHost` 用 `spreadRoot.scaleX/scaleY` 做 View 变换，
1080px 底图被插值到最多 4×；`InkView` 也是 View 尺寸位图缓冲，**笔迹一起糊**。
整页按 4× 重渲染需 4320×6112 ≈ 105MB/张，两层三缓冲直接 OOM，必须分块。

**架构：viewport 驱动，无 View 缩放**

新增每页独有的 `Viewport`（ViewPager2 同时有多页，用单例会串倍率）。
`ZoomHost` 只维护 scale / tx / ty 数值，不再对 `spreadRoot` 做
scaleX/scaleY/translation；子 View 在 `onDraw` 里按同一组数自绘：

```
s        = bucket(scale)                   // 1 / 1.5 / 2 / 3 / 4 档
lw, lh   = width*s, height*s               // 逻辑画布（放大后整页像素）
left     = width*(s-1)/2 - tx              // 可见窗口左上角
top      = height*(s-1)/2 - ty
canvas.translate(-left, -top)              // 之后都按逻辑坐标绘制
```

- **底图**：v14 的纵向条带升级成二维 400×400 网格块，
  `PdfRepo.renderTile()` 用 `A = lw / pageWidth` 的矩阵只渲染该块，

## 浏览模式 v16：手势全恢复 + 默认浏览 + 点击切做题

**用户报告**：点双箭头切到浏览模式后，上下滑动、任意手势放大缩小、
翻页全都不起作用。

**根因（两个叠加，不是各手势分别坏）**

1. `InkView.dispatchTouchEvent()` 在 `browseMode` 直接 `return false`；
   `TiledPageView` / `PageContainer` / `spreadRoot` / `ZoomHost` 都不消费
   `ACTION_DOWN`。Android 规则：**DOWN 无人消费，后续 MOVE /
   POINTER_DOWN / UP 不再派发给这棵 View 树** → `ZoomHost.handle()`
   连事件都收不到，双指缩放 / 上下平移 / 双指横滑翻页「一起失效」。
2. `ZoomHost` 在 `ACTION_DOWN` 无条件
   `requestDisallowInterceptTouchEvent(true)`，ViewPager2 靠
   `onInterceptTouchEvent` 拦横向滑动，被禁后单指翻页也没了。

**P0 修触摸链**

- 浏览模式由 `ZoomHost` 自己消费 `DOWN`，整条事件链恢复
- `disallow` 只在做题模式调用；浏览模式把横向拦截权还给 ViewPager2
- 多指开始才临时锁父级拦截（双指横滑翻页不被抢），结束恢复
- 清掉 `ACTION_POINTER_DOWN` 时的 `super.dispatchTouchEvent()` 重复分发；
  做题模式多指开始时给 InkView 补发 `ACTION_CANCEL` —— 否则第一指
  起的那一笔永远收不到 `UP`，会残留在 `live` 缓冲（顺手修掉的真 bug）
- `currentZoom` 是全局值、切页不重置 → `updatePagerInput()` 改按
  `PagesAdapter.zoomOf(当前页)` 判断；`onPageSelected` 也补一次刷新

**P1 单指上下滑（推荐口径）**

浏览模式且页面有纵向超出（`panExtraY>0` 或 `scale>1`）时，
单指纵向拖动 = 上下平移；横向仍交给 ViewPager2 翻页。
判定抽成 `GestureArbiter` 纯函数（纵向 > 阈值且 > 横向），
竖屏 FIT 无纵向超出时单指上下不产生动作、也不会误触。
双指同向拖动仍可用，两套并存。

**P2 默认浏览 + 两态**

- `UiState` 默认 `true`；`browseMigrated` 升级标记让老配置也回浏览。
  推荐口径「记住上次模式」：切到做题写进偏好，重开保持做题
- 按钮语义反转：**做题态高亮**；图标两态 —— 浏览态显示笔（点它去做题）、
  做题态显示页面横线 + 滑动箭头（点它回浏览），读屏两态描述，零文字
- 绘图按钮不再在浏览态悄悄切工具却画不上：**点任意绘图按钮直接
  切回做题并选中该工具**（保持可点击，比真禁用更顺一步到位）
- 悬浮橡皮在浏览态隐藏；若正处橡皮态切浏览则复位

> 一处取舍：绘图按钮没有设 `isEnabled=false`。真禁用会让点击彻底
> 没反应，与「默认浏览后天天要点」冲突；改成点击即退出浏览更符合
> 计划里「更顺，一步到位」的优先级，视觉仍用 0.4f 表示当前不可用。

**P3 验收**
  52. 默认打开就是浏览：单指左右翻页、上下滑（页面超出时）、双指缩放都生效
  53. 点笔图标切做题：单指写字落点准、双指缩放不留残笔、横向不被误翻页
  54. 再点回浏览：无残留笔迹、悬浮橡皮消失、翻页恢复
  55. 放大后翻到下一页仍可横向翻页；音量键/底栏箭头/进度条/边缘热区两态都通

## 统一返回栈与侧滑退出 v23

用户要求：**返回逻辑和手机返回一致，侧滑返回上一界面，连续侧滑两次退出**；
补充：**首页时也要侧滑两次，第一次侧滑进行提醒**。全做、按推荐。

**诊断：当前根本没有返回栈**

全工程 `onBackPressed` / `OnBackPressedDispatcher` / `OnBackInvokedCallback` /
`finish()` 命中均为 0 —— 系统返回键与侧滑走默认行为，**一次就退出**；而
「更多 → 返回书架首页」走 `showHome()` 只切界面、不结束 Activity。两条路径
不一致。

还有一个必须先绕开的坑：`targetSdk = 35`，Android 15 对 targetSdk≥35
**强制启用 OnBackInvoked、不可关闭**，直接覆写 `onBackPressed()` 在高版本
收不到事件。Manifest 原先也没写 `enableOnBackInvokedCallback`。

侧滑「不像手机」是三层叠加：
1. `edgeLeft/edgeRight` 贴屏幕左右边缘、`match_parent` 高，
   `attachEdge()` 在 `ACTION_DOWN` 就 `return true` 消费并锁定父级拦截 ——
   系统返回正是从这条边缘起手
2. v16 浏览态单指横滑交给 ViewPager2 翻页，边缘与中间同一动作结果不同
3. `hideSystemBars()` 在 API 26/28 用 `IMMERSIVE`（非 STICKY）+ 「栏一露出
   立刻重 hide」；legacy 沉浸下从边缘滑入会先显示系统栏并**消费这次滑动**，
   荣耀 10 / EMUI 8.1/9 上很可能就是「第一次侧滑没反应」的来源

第 3 条涉及厂商 ROM 手势实现，属静态推断，需真机确认；前两条是代码事实。

**口径：合并模型**

用户同时要求「连续两次退出」「首页也两次」「第一次提醒」，因此：
做题态第一次侧滑 = **返回上一界面（回首页）**，同时记为退出确认第一下并提醒；
首页第一次侧滑 = 提醒（不退出）；2s 窗口内第二次 = `finish()`。
这样从卷子里 / 从首页冷启动**都是两次退出**，且第一次都有提醒。

**P0 返回栈（`handleBack()` 优先级）**

`setupBackNavigation()` 用 `OnBackPressedDispatcher.addCallback`
（`androidx.activity:activity-ktx:1.9.3` 自动桥接 OnBackInvoked），
API 26–35 一套代码；Manifest 显式 `enableOnBackInvokedCallback="true"`。

1. 套索选区 active → `cancelSelection()`，重置确认计时
2. `barsHidden` → `toggleBars(false)` 恢复工具栏，重置确认计时
3. 做题态 → `goHome()`（`saveSessionNow()` + `showHome()`），记为第一下 + 提醒
4. 首页根 → 窗口内第二次 `finish()`，否则 `flash(back_exit_hint)` 提醒

`PopupWindow`（2 个，focusable）与 `AlertDialog`（8 个）是独立 Window，
系统自行 dismiss，dispatcher 不介入。`openingDocument`（SAF / 文档加载）
期间不接管。提醒文案「再侧滑一次退出墨页」是全 App 唯一一处提示文字，
由用户本轮明确要求；零动效、零其他说明小字。

**P1 让侧滑真的能触发**

- `edgeLeft/edgeRight` 从贴边内移 **24dp**（`translationX = safeL + dp(24)` /
  `-safeR - dp(24)`），屏幕最外侧留出没有任何 View 消费 `ACTION_DOWN` 的
  系统返回手势区；热区仍可点击翻页，只是不再贴边
- `attachEdge()` 删掉全部父级拦截锁定，横向裁决权还给系统 / ViewPager2
- API<30 的 `SYSTEM_UI_FLAG_IMMERSIVE` → **`IMMERSIVE_STICKY`**，避免首次
  边缘滑动被「先显示系统栏」吞掉；保留可见性监听器立刻重 hide，
  状态栏依旧不常驻（与 v14 的细微取舍见下方限制）
- 全程不调用 `setSystemGestureExclusionRects`（工程本来就没有）
- 中间区域横向滑仍翻页；边缘起手 = 返回，两者不重叠

**P2 配套**

`goHome()` 抽出，`handleBack()` 与「更多 → 返回书架首页」共用同一函数，
菜单路径不弹提醒；`goHome()` 先 `saveSessionNow()`，补上 v21 之后
「返回首页这一跳漏存逐页视口」的缺口。首页态不会误返回到已销毁的文档。

**P3 验收**

静态断言：无 `onBackPressed` 覆写、dispatcher 已注册、四级优先级、
2s 窗口、边缘热区不消费最外侧、无父级拦截锁定、STICKY、
Manifest 显式启用。`verify.sh` 补 4 条（共 69）。真机荣耀 10 验：
卷子里侧滑 → 回首页且记录仍在 → 再侧滑 → 退出；首页冷启动侧滑 1 → 提醒、
侧滑 2 → 退出、间隔超 2s 重新计；隐藏工具栏 / 选区 / 浮层逐级关闭；

**已知限制（如实说明）**

1. `IMMERSIVE_STICKY` 在部分 EMUI 上会让系统栏极短暂半透明露出后被
   监听器压回，与 v14「绝对不露」有细微取舍；换来的是首次侧滑不再被吞。
   真机若仍被吞，可进一步改为「只 FULLSCREEN、不 HIDE_NAVIGATION」。
2. Android 14+/15 预测式返回会在侧滑时显示「回桌面」预览，而第一级其实是
   App 内部切页，观感有轻微错位；系统动画，不影响实际行为。
3. 从卷子里退出需要「回首页 + 退出」两次，中间的提醒文案同时承担
   「已到根页」与「再滑退出」两重语义，这是为满足两次退出的合并口径。

## 竖屏上下滑浏览 v26

**诊断**：不是手势被抢，是竖屏根本没有「可上下移动的内容」。v19 的 FILL

于是 v16 那条单指纵向平移的开关 `canPan = panLimitY() > 0.5f` 恒 false，
上下 MOVE 只更新 `lastSingleY`；双指同向拖动的 `ty += dy` 也被 0 边界钳回。
横向 `panLimitX()>0` 归 ViewPager2，所以只剩左右翻页。

**P0 竖屏上下滑**：`applyPagerOrientation()` 把竖屏 ViewPager2 切到
`ORIENTATION_VERTICAL`，横屏保持 `HORIZONTAL`。跨页纵向滚动由系统
RecyclerView 原生接管，页面本身仍一屏完整、不被上下裁切，v19 铺满保住。

- 竖屏 1×：**上下滑 = 连续跟手浏览**（当前页推走、相邻页接上）
- **左右滑翻页保留**：VERTICAL 后横向不再触发 pager 滚动，由
  `GestureArbiter.isHorizontalFlip` 补一次离散翻页（`horizontalFlipDone`
  防重复）；1.2 倍方向比避免手写斜划误翻
- 放大态：`updatePagerInput()` 关掉 `isUserInputEnabled`，纵向自动回到
  ZoomHost 的页内平移；横屏 WIDTH 的 `panLimitY>0` 分支完全不回归
- 做题态：InkView 消费 DOWN，单指写字不受影响
- 切方向时保存并恢复 `currentItem`，不做平滑滚动避免闪帧

**P1 流畅度 / 跟手度（6 处）**

1. **死区补偿**：`singlePanning` 判定成立时把阈值内累积的位移一次性补回
   `ty/tx`，起步不再白丢 16dp，连续平移 1:1 跟手
2. **预览全程跟手**：DOWN 后第一次 MOVE 即置 `deferHighResolution=true`
   （原来要等 16dp 判定），0.5× 预览网格从第一帧就托底
3. **帧对齐**：沿用并行提交在 ZoomHost 层落地的
   `scheduleTransform()` / `flushTransform()`（`postOnAnimation` 合帧），
   本轮新增的死区补偿与页内平移一律走同一入口，一帧只重算一次 viewport
4. **惯性 fling**：由 VERTICAL ViewPager2 的 RecyclerView 原生提供
5. **边界回弹**：原生 EdgeEffect，竖向时着品牌蓝 `#2F6FED`（内部
   RecyclerView 拿不到则静默跳过），首/末页不硬停
6. **方向预取**：`offscreenPageLimit=1` 按滚动方向预取前后各一页首屏，
   配合 0.5× 预览网格，快甩不出白块

**P2 配套**：页码、进度条、书签、会话归一化位置、缩略图、导出按逻辑页
不变；横屏 v14 的 WIDTH / 双页并排一概不动；v23 侧滑返回让出的屏幕边缘
仍归系统手势；零文字、首页与桌面图标不动。

**已知边界**：竖屏横向翻页沿用页切换动画（VERTICAL 下表现为相邻页纵向
滑入），功能保留但方向与手势不同；屏幕最外侧 14dp 边缘热区仍优先给
翻页/系统手势，在极边缘起手的上下滑可能被热区先接走。

## 默认铺满 · 首次打开即生效 v27

**用户口径**：应用默认文件铺满屏幕，首次打开文件时直接就是铺满态，
不需要先去「更多」里点一次「铺满屏幕」。

**诊断**：`fillScreen` 的字段默认值本来就是 `true`，但有两处会把首次
打开拉回 FIT：

1. `finishOpenUri()` 里 `state.displayMode = session.displayMode`，
   旧会话（或用户此前手动切过「适应屏幕」后留下的 `modeChosen=true`）
   会让竖屏走 FIT，页面按宽度 contain，在 19:9 屏上上下各留一大块米白；
2. 老版本偏好里存过 `fillScreen=false` / `displayMode=FIT` 时，
   `loadPrefs()` 直接读回，升级后不会自动回默认。

另外 `UiState.landscape` 初值是 `true`，若某条打开路径早于
`applyOrientationLayout()`，`currentFitMode()` 会把竖屏误判成横屏，
FILL 分支根本不进。

**P0 升级迁移**：`loadPrefs()` 新增 `fillMigrated` 标记。未迁移时一次性
强制 `fillScreen=true` / `displayMode=WIDTH` / `modeChosen=false`，并立即
写回偏好；`savePrefs()` 也持久化该标记。**只迁移一次**，之后用户在
「更多」里主动切到「适应屏幕 / 适应宽度」仍照常记住，不每次覆盖。

**P1 首次打开强制**：`finishOpenUri()` 开头先同步
`state.landscape`（按当前 configuration），随后在 `!modeChosen` 时强制
`fillScreen=true` + `displayMode=WIDTH`。覆盖三条入口：冷启动恢复上次
文档、SAF 新选文件、从首页点浏览记录；横屏仍走 v14 的 WIDTH，不受影响。
`ad.fitMode = currentFitMode()` 随即按新状态算成 `PageContainer.FILL`。

**结果**：竖屏首次打开即按可用高度放大（荣耀 10 有栏约 1.27×、
隐藏栏约 1.53×），上下零留白、文字比 1× 更清晰；左右约 13%/26% 的
内容用双指横拖看全。菜单里「铺满屏幕」的选中态与实际模式一致。

**不变**：横屏 FIT/WIDTH/DOUBLE、v26 竖屏上下滑、v19 智能铺满的
`fillScale`/`refreshHostBounds`、v16 默认浏览、v23 返回栈、首页两态、
零说明性小字。

**验收**：静态断言（迁移标记读写、首次打开强制、方向同步、菜单选中态）
+ `verify.sh` 补 2 条（共 78）+ README。真机荣耀 10 验：清数据首次安装、
旧版升级、冷启动恢复、SAF 新选、从记录点开，五种首次打开都直接铺满；
手动切「适应屏幕」后重开仍尊重用户选择。

## 任意文档可用 · 浏览记录格式色徽标 v28

**用户口径**：所有文档都可以用；浏览记录显示效果和 PDF 一样；左侧 logo
参考主流软件的做法。

**参照对象**：微信 8.0.78 起的文件图标、WPS / Microsoft Office /
百度网盘、Google Drive 都是同一套约定 —— **彩色圆角方块 + 白色粗体缩写**，
PDF 红、Word 蓝、Excel 绿、PPT 橙；Drive 也是「每个文件左侧一个彩色小方块」。
另一套是 Drive 新版「白纸轮廓 + 单色字母」，扫读更慢且与现有红块冲突，未采用。

**诊断**：代码里三处写死 —— `item_home_card.xml` 的 `pdf_badge_bg` 红底 +
`text="PDF"`；`Recents.Item` 无类型字段；`openUri()` 硬编码
`PdfRepo(this, uri)`，非 PDF 抛异常直接回首页。文件选择器
`OpenDocument()` 其实没限类型，入口能选任意文件，坏在渲染层。
副行 `「2 / 4 · 大小」` 含页码，对图片 / 压缩包不成立。
好消息：`Fingerprint.from` 本来就是通用字节流（长度 + 头/中/尾 64K），
`InkStore.fingerprint` 走 `openInputStream`，任意格式都能算，无需改算法。

**P0 格式色徽标**：新增 `FileKind` / `FileType`（纯 JVM）。34dp 圆角方块、
4dp 圆角、白粗体、`scaleX 0.84`、字距 -0.03 全部沿用；运行时按类型换底色和字。
- PDF `#D7463B` + 16sp「PDF」**显式仍用 `pdf_badge_bg.xml`，逐像素不变**
- W `#2B579A` / X `#217346` / P `#D24726` 单字母 16sp
- IMG 紫 `#7B61D9` / TXT 灰 `#6B7280` / ZIP 黄 `#E0A22E` 12sp
- 其它中性灰 `FILE` 10sp
- 卡片版式、完整文件名（含后缀不截断）、蓝点、点击续读、长按菜单零改动

**P1 类型识别与记录**：`Recents.Item` 加 `kind` / `mime`；写入时取
`ContentResolver.getType(uri)`，为空按 `DISPLAY_NAME` 后缀兜底。
`all()` 对无 `k` 字段的老记录按文件名回填类型 —— **不丢记录、不用重导入**。
`custom` 手动改名仍不被覆盖。指纹按文件字节算，不会串记录 / 串笔迹目录。

**P2 打开链路（范围 A+B）**：抽 `PageSource` 接口（count / ratio /
renderTile / render / thumb / cacheId），`PdfRepo` 改为实现它；
`PagesAdapter` / `TiledPageView` / `OverviewAdapter` / `PageComposer` /
`PdfExporter` / `MainActivity` 全部依赖接口而非具体类。

- **PDF**：原管线一字不动
- **图片**：`ImagePageSource` 用 `BitmapRegionDecoder` 按可见块解码，
  不「整页缩成大图再放大」；少数不支持区域解码的格式回退到受限整图
- **纯文本**：`TextPageSource` 按行分页，`Canvas.drawText` 直接画到块上，
  放大是矢量重绘而非位图插值，4× 仍锐利
- **旋转**：`RasterRotation.inverse()` 把旋转后画布的块反算回源画布的
  轴对齐矩形，渲染后转回来，输出尺寸仍精确 tw×th；不需要整页大位图
- **Office / EPUB / 压缩包 / 其它**：`ACTION_VIEW` 转交系统 App，
  `FLAG_GRANT_READ_URI_PERMISSION`，回来照样 `recents.add` 记一条、排最前；
  冷启动恢复对外部类型留在书架，避免一启动就跳到别的 App
- **导出 / 缩略图 / 批注备份**：因接口统一，内嵌类型照样可用（可把图片、
  文本连同批注烘成 PDF）；转交类型不进文档态，也就不存在「导出空壳」
- **副行按类型**：有页概念（PDF / 文本）→ `2 / 4 · 11.32 MB`；
  图片 / Office / 压缩包 → `11.32 MB · IMG`，不编造页码、不加说明性灰字

**已知限制**
1. Office / EPUB 仅转交系统，**不在墨页里批注**；端上还原排版需引重库，
   荣耀 10 上体积与内存都吃紧，按推荐范围没做。
2. 图片放大受源文件分辨率限制（位图不能凭空变矢量）；未放大时按 1:1
   区域解码，清晰。纯文本放大是矢量，不受此限。
3. 文本按固定字宽折行，中英混排的断行不如系统文本排版精细。
4. 外部类型没有「页码 / 缩放 / 平移」会话，续读定位不适用。

**验收**：`FileTypeTest`（8 条：映射、色值、回填、分页、旋转逆映射）
+ 静态断言（PDF 徽标资源与 16sp 未改、接口覆盖、老记录回填、外部转交、
无脏记录）+ `verify.sh` 补 4 条（共 82）+ README。真机荣耀 10 验混排
6 种类型一眼可分、Word 能转交并回记、图片 / 文本内嵌能翻页批注缩放、
老记录不丢、PDF 卡片与改造前叠图一致。

**边界**：v27 默认铺满、v26 竖屏上下滑、v23 返回栈、v22 首页圆盘、
v21 放大镜短闪、v20 ⇄/★、首页两态、红底 PDF 徽标、零说明性小字
全部原样保留。
